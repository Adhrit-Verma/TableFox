Security

How we protect your database

Giving any service a database password is a real decision. Here is exactly what TableFox does with it, what it can and cannot do, and how to avoid sharing it at all.

Your password

  • Entered on TableFox's own page, over HTTPS, through a private single-use link. Never typed into a chat.
  • Tested before it is saved. TableFox connects once and refuses any user that can write, change the schema or administer the database.
  • Encrypted before storage with Fernet (AES-128 plus an HMAC-SHA256 integrity check), in a database separate from the TableFox server.
  • Decrypted only in memory, only to open a connection to your database.
  • Never shown to your assistant, never written to logs, never included in error messages.

Read-only at every layer

Even if one guard failed, the others still stop a write. A request has to pass all of them:

  1. A read-only database user, which TableFox checks before accepting it.
  2. Only SELECT and WITH statements are accepted. Everything else is rejected before reaching your database.
  3. Every query runs in a read-only transaction with statement and lock timeouts.
  4. Each query is planned first (EXPLAIN), and queries over cost and row limits are refused.
  5. Personal-data columns such as emails, phone numbers and password hashes are blocked from results.

Isolation between users

Every signed-in user gets a separate connection pool, cache and audit trail. A user can only reach the databases they saved themselves; names are looked up only within their own account.

Connections must use SSL and a public address. TableFox checks the address before every connection and locks onto it, so a database host cannot be pointed at TableFox's own network.

What we log

For each tool call: the time, the action, object names (such as a table name), counts, and a one-way fingerprint of the SQL. Never the SQL text, your rows or your password. We keep a cache of table and column names so answers are fast, and never your data. Full detail is in the privacy policy.

You stay in control

  • Create a dedicated read-only user just for TableFox. You can change its password or drop it at any time, and TableFox loses access immediately.
  • Remove any saved database from your private manage page.
  • Disconnect TableFox in your assistant to stop all access.

Don't want to share it? Run TableFox yourself

TableFox is open source under the MIT license. You can run the same software on your own computer: your password stays in a file on your machine, nothing is sent to our server, and it also works with databases on private company networks. Self-hosting takes about five minutes.

What is not done yet

We would rather you know:

  • TableFox has not had an independent security audit. The code is public for anyone to review.
  • The hosted service runs on free infrastructure operated by one maintainer.
  • All saved connections are protected by one server encryption key. Support for rotating that key is planned.
  • Per-user rate limits are basic today: two connections per user plus query timeouts.

If any of these matter for your data, self-host.
