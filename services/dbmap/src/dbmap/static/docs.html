Overview

TableFox connects an AI assistant to your PostgreSQL database. When you ask a question, it finds the few tables that matter and runs safe, read-only queries. It can never change your data.

  1. Add TableFox to your assistant with this address and sign in:
https://tablefox.onrender.com/mcp
  1. Connect a database on TableFox's private page, using a read-only user.
  2. Ask anything, like "Which 5 products earned the most revenue?"

Prefer not to share a database password with a hosted service, or is your database on a private network? Run TableFox on your own machine. It works the same way and the password never leaves your computer.

ChatGPT and Claude

ChatGPT

  1. Open Settings → Security and login and switch on Developer mode.
  2. Go to Plugins, choose +, then Add custom MCP server.
  3. Enter the address above, choose OAuth sign-in, and create it.
  4. Sign up or sign in on the TableFox page that opens, then start a new chat.

Claude (claude.ai or Claude Desktop)

  1. Open Settings → Connectors and choose Add custom connector.
  2. Paste the address above and sign in when asked.

Connect a database

Ask your assistant anything, for example "What tables are in my database?". The first time, TableFox replies with a private link. It works once and expires after 10 minutes. Open it and fill in:

FieldWhat to enter
NameA short name you will use when asking, like sales
Host and portYour database address, like db.example.com and 5432
DatabaseThe database name, like postgres
User and passwordA read-only user made for TableFox
SSLRequire

Choose Test and connect. TableFox checks the user really is read-only, then saves the details encrypted. Your assistant never sees them.

Never paste a database password into the chat. Always use the private link.

Create a read-only user

TableFox only accepts users that cannot change anything. Run this once as your database administrator, replacing the <placeholders>:

create role tablefox_reader login password '<long random password>';
alter role tablefox_reader set default_transaction_read_only = on;
grant connect on database <your_database> to tablefox_reader;
grant usage on schema public to tablefox_reader;
grant select on all tables in schema public to tablefox_reader;
alter default privileges for role <table_owner> in schema public
  grant select on tables to tablefox_reader;
  • Neon: run it in your project's SQL Editor. The owner is usually neondb_owner. Copy the host from Connect.
  • Supabase, AWS RDS and others: the same SQL works. Make sure the database accepts connections from the internet over SSL.
  • PostgreSQL 14 or older: everyone can create tables in public by default, so also run grant create on schema public to <table_owner>; then revoke create on schema public from public;.
  • Other schemas: repeat the usage and select lines for each schema you want TableFox to read.
  • Keep sensitive data out: instead of select on all tables, grant only the tables TableFox needs, or only some columns, for example grant select (id, name, country) on customers to tablefox_reader;. Data the user cannot read can never reach your assistant.

Ask questions

Specific questions work best:

  • Which 5 products earned the most revenue last quarter?
  • How many orders were cancelled per country this year?
  • Which customers signed up but never ordered?

TableFox refuses anything that would change data (delete, update, create table). It also leaves out columns named like emails, phone numbers and passwords, but that filter goes by column name, so it is a safety net rather than a guarantee.

Several databases

Ask for "the TableFox link to manage my databases" to add more, each with its own short name. If a question does not say which one, the assistant asks. Answer with the name, like "use sales". The same page lets you remove a database at any time.

Run TableFox yourself

Self-hosting keeps your database password on your own computer and works with databases on private networks. There is no sign-in; your assistant starts TableFox directly.

  1. Install Python 3.11 or newer, then in a terminal:
git clone https://github.com/Adhrit-Verma/TableFox.git
cd TableFox
python -m venv .venv
.venv/bin/pip install -e services/dbmap

On Windows use .venv\Scripts\pip.

  1. Create a file named .env in that folder with your read-only user:
DATABASE_URL=postgresql://tablefox_reader:<password>@db.example.com:5432/postgres?sslmode=require
  1. Point your assistant at it. Use your real folder path; on Windows the command ends in .venv\Scripts\dbmap-mcp.exe.

Claude Code

claude mcp add tablefox \
  --env DBMAP_ENV_FILE=/path/to/TableFox/.env \
  -- /path/to/TableFox/.venv/bin/dbmap-mcp

Codex

codex mcp add tablefox \
  --env DBMAP_ENV_FILE=/path/to/TableFox/.env \
  -- /path/to/TableFox/.venv/bin/dbmap-mcp

Cursor, Gemini CLI, Windsurf, Claude Desktop

{
  "mcpServers": {
    "tablefox": {
      "command": "/path/to/TableFox/.venv/bin/dbmap-mcp",
      "env": { "DBMAP_ENV_FILE": "/path/to/TableFox/.env" }
    }
  }
}

VS Code

{
  "servers": {
    "tablefox": {
      "type": "stdio",
      "command": "/path/to/TableFox/.venv/bin/dbmap-mcp",
      "env": { "DBMAP_ENV_FILE": "/path/to/TableFox/.env" }
    }
  }
}

Restart your assistant after changing .env.

Instructions for your agent

Paste this into your project's agent instructions (AGENTS.md, CLAUDE.md or your tool's rules) so it uses TableFox well:

## Database (TableFox)
- For any question about the database, call database_task_context with the full question first.
- Then answer with at most five bounded SELECT/WITH statements in one database_readonly_batch call,
  using only the joins it returned.
- TableFox is read-only. Never attempt writes, and never ask for database credentials in chat.
- If several databases are connected, pass the right name as the database argument (ask if unclear).

Troubleshooting

You seeWhat to do
This link has expired or is incompleteAsk for a new link. Each one works once, for 10 minutes.
'…' is not read-onlyCheck the user name in the message. Use your read-only user, not the owner or admin account.
The server does not accept SSL connectionsTurn on SSL for your database. TableFox requires it.
The database host must be a public internet addressThe hosted service cannot reach private networks. Self-host instead.
Wrong user or passwordCheck the read-only user's password.
The assistant can't find a TableFox toolRefresh or reconnect TableFox in your assistant's connector settings, then start a new chat.

Current limits

  • PostgreSQL only for now.
  • Public databases only on the hosted service. Private networks need self-hosting.
  • Free hosting. The hosted service runs on free infrastructure kept awake by a health check. If it has been idle, the first request can take up to a minute.
  • Usage limits are basic: each user gets at most two database connections and every query has a timeout. Stricter per-user rate limits are planned.

How we measure

We compare TableFox's two calls with what a careful developer does without it: search the database catalog for the right tables, then write SQL by hand. Both paths run the same questions against the same database, and the answers must match.

  • Speed: end-to-end time per question, reported as median and 95th percentile.
  • Size: how much text each path sends to the model, estimated in tokens.
  • Accuracy: whether TableFox found every table the answer needs, and whether its answers match the hand-written SQL.

Our latest test used a 71-table, 25-million-row database and 70 questions, each run 3 times: a median of 96 ms per question against 282 ms the usual way, about 28% fewer tokens, and 64 of 64 queries returning identical rows. It also found weak spots we are working on. See the full results. Your results will vary with your database and network.
